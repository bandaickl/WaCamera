## 1.0.1：NeoForgeシェーダー録画の移植（2026-10-12）

NeoForge 1.21.1へIrisの独立シェーダー録画を移植しました。Forgeの機能は1.0から変更していません。

| 確認項目 | 今回の範囲・結果 |
| --- | --- |
| 対象API | Minecraft 1.21.1用Iris 1.8.12とSodium 0.6.13の実JARを読み取り、反射APIのシグネチャと必要なバイトコードを照合。Irisの公開直前のソースも参照 |
| 実装 | 独立pipeline・gbuffer・影・履歴・Sodium programs、共有状態の退避・復元、終了時の資源解放を追加 |
| ビルド | 修正反映後のNeoForgeのassemble、Forgeのassemble／reobfJarが成功。テストやゲーム起動を伴わない |
| Minecraft起動・ゲーム操作 | 利用者の希望により未実施 |
| 自動テスト・音声テスト・実録画 | 利用者の希望により未実施 |
| NeoForgeのDH併用 | シェーダー有効＋Distant Horizonsは未対応として録画開始を拒否。ガードのゲーム内動作は未検証 |

今回のGitHub更新はソースが対象です。公開済みv1.0 Releaseを維持し、両版の1.0.1 JARと`SHA256SUMS.txt`をローカルの`dist/1.0.1/`へ配置しました。1.0.1のReleaseは公開していません。

両JARを読み取り、MODメタデータとImplementation-Versionが1.0.1であること、LICENSE・THIRD_PARTY・ロゴ・Windows音声ヘルパーの同梱を確認しました。NeoForgeの新規シェーダー関連クラス、Mixin pluginと設定、言語JSONも確認しました。Iris・Sodium本体は同梱していません。この確認はパッケージ内容の確認であり、ゲーム内動作の検証ではありません。

最終ビルドのログは`.tools/neo-1.0.1-assemble-final.log`と`.tools/forge-1.0.1-assemble.log`です。ビルド成功は、Irisを入れたゲーム内でのMixin適用や録画像の確認を意味しません。

NeoForgeで実際にシェーダー効果が動画へ反映されるか、通常画面を維持できるか、影・TAA・自己表示・異なる解像度・停止後の再録画・再読込・長時間のGPU資源使用量は未検証です。Iris・Sodiumはシェーダーを使う場合の追加構成で、通常録画の必須依存にはしていません。

**以下の1.0／alpha版の節は、その版で実施した過去の記録です。** 当時の「NeoForgeへ未移植」という説明は当時の実装状況を示し、1.0.1の現在の実装状況はこの冒頭節を参照してください。Forgeのシェーダー録画結果をNeoForgeの実録画検証として扱いません。

## alpha.7：別ウィンドウ操作中の録画継続（2026-10-08）

録画準備・カウントダウン・録画中だけ、フォーカス喪失による自動ポーズを抑止します。通常のシングルプレイでゲームが実際に一時停止した場合は録画を終了して保存します。マルチプレイやLAN公開中のEsc画面ではゲームが停止しないため録画を継続します。プレビューと待機中はMinecraft本来のフォーカス喪失時の動作へ戻ります。`pauseOnLostFocus=true`を保持したまま、録画中の読み取りだけを切り替えることを検証しました。

Windows 11／GeForce RTX 4070 Tiで、VSync無効・最大60fpsを使用しました。Forge 1.20.1／47.4.10／Java 17とNeoForge 1.21.1／21.1.251／Java 21の専用新規ワールドで実行し、マスター音量は全期間0、録画の音声も無効です。既存のユーザーセーブは開いていません。

完成MP4の数値と音声トラックなしはFFprobeで確認しました。初回の通常構成の両版と、チャット追加後のForgeシェーダー構成は、最終PASSとワールド保存・ゲーム終了を確認しています。上記の手動ポーズ試験はEscキー入力の自動操作ではなく、Escから呼ばれるポーズ処理を直接実行したものです。

初回と反復のForgeシェーダー試験では、テストが「画面が開いていないこと」まで条件にしていたため検査に失敗し、テストランナーがゲームを終了しました。その際にTでチャットを開いたとの報告があり、ゲームを一時停止しないチャットまで異常扱いする検査の問題を確認しました。Minecraftのクラッシュ報告は新規生成されていません。検査条件を実際の一時停止と一時停止画面の有無へ修正し、チャット入力を加えたForgeの最終試験は全項目が成功しました。

追加の文字入力試験は`ChatScreen.charTyped`を呼び、`EditBox`から文字列を読み戻したものです。物理的なTキー操作やOSのIMEによる日本語変換を自動検証したものではありません。

利用者の作業を妨げるため、依頼に従って追加のゲーム試験を終了しました。NeoForgeの追加チャット入力試験は未完了です。後続試験でPauseScreenが開いた原因は、この記録から断定しません。

NeoForgeと初回のForgeシェーダー試験では、実最小化中の録画の45／75フレーム目が異なることをMD5で確認しました。約2秒地点の画像も目視し、本人と背景が映り、シェーダー側では効果も保持されていることを確認しています。最小化中の映像が一枚の静止画や黒画面のまま進む現象は、この確認区間ではありませんでした。

フォーカスの再現試験と実最小化の試験は区別しています。実最小化を確認した条件も短時間・上記のPC構成に限られ、VSync有効時、別GPU／OS、長時間の最小化、OSのスリープは今回検証していません。

通常構成の初回ログは`.tools/forge-alpha7-background-smoke.log`、`.tools/neo-alpha7-background-smoke.log`です。シェーダーの初回・再確認・反復はそれぞれ`.tools/forge-alpha7-background-shaders.log`、`.tools/forge-alpha7-background-shaders-recheck.log`、`.tools/forge-alpha7-background-shaders-repeat.log`です。チャット追加後は`.tools/forge-alpha7-background-chat.log`（シェーダー有効）と`.tools/neo-alpha7-background-chat.log`に記録しています。各ゲームの`run/wacamera/smoke-background.txt`には結果と実MP4パスを記録します。再実行は`runClient -Psmoke -PsmokeBackground -PsmokeFfmpeg=<実行ファイル>`、実最小化も試す場合は`-PsmokeBackgroundIconify`を追加します。

## alpha.4のシェーダー有効時の二視点録画

Forge 47.4.10＋Embeddium 0.3.31＋Oculus 1.8.0＋Distant Horizons 2.3.4-b＋Complementary Unbound r5.6を隔離インスタンスで使用しました。Iris APIがシェーダー有効と報告する状態で、昼夜それぞれの固定カメラ録画を実行しています。通常の操作画面は960×600、録画は1280×720・30fpsです。

白い床、柱と梁、発光ブロックの専用風景を新規フラットワールドに作り、昼と夜の時刻・天候を固定しました。通常描画を5秒待ち、同じカメラ位置の単独プレビューを6秒表示して参照画像を取得してから録画します。録画の最初の2秒は本人を静止させ、その後に移動・回転・ジャンプ・木材の設置を行います。音量は全期間0です。

## alpha.3の地点コマンド

Forge 1.20.1とNeoForge 1.21.1の実クライアントに登録されたコマンドディスパッチャーで実行しました。

- GUIを開閉しただけでは初期地点を登録済みとせず、`/wac cam` が1・2・3と自動追加されること。
- 現在のカメラのXYZ・yaw・pitchを取得し、番号指定で上書きしても地点数と既存IDが変わらないこと。
- XYZ・yaw・pitchの直接入力。飛び番号、未登録地点、pitchの上限超過、別ディメンションを拒否し、設定を変えないこと。
- `/wac goto 2` で、クライアントと内蔵サーバー双方のプレイヤーの目線XYZ・yaw・pitchが保存値へ一致すること。
- 泳ぐ姿勢からの移動要求を拒否し、移動前後の姿勢差による目の高さのずれを避けること。
- 録画準備中の地点変更と移動を拒否すること。

コマンド試験に続けて、両版の通常画質で固定・曲線・同方向の3ショット、建築、インベントリー、プレビュー復帰を再確認しました。各ショット4秒、通常カメラの検査64～65回、木材設置3～7個。alpha.2で確認したFabulous設定と10分の録画モジュール試験は、alpha.3では再実行していません。

## 実行方法

`scripts/build.ps1` は音声ヘルパーのビルド、共通テスト、両MODのビルドを実行します。FFmpeg統合試験は `WACAMERA_TEST_FFMPEG`、プロセス音声取得は `WACAMERA_TEST_AUDIO_HELPER` へ実行ファイルのパスを設定してください。10分試験の手順は `recorder/README.md` にあります。音再生用の環境変数は設定しないでください。

ゲーム内試験は各ローダーの `runClient -Psmoke -PsmokeAudio -PsmokeFfmpeg=<パス>`。専用の新規フラットワールドを作り、既存セーブは開きません。結果とPNGは `run/wacamera/smoke-*` に保存します。

`-PsmokeFabulous` を加えるとプレイ画面のFabulous設定で試験します。録画側はFancy相当の独立描画です。

Forgeの描画MOD互換試験は、ローカルの`.tools/compat-mods/`へ対象のEmbeddium・OculusのJARを用意し、`-PcompatMods`を加えます。DHも使う場合は同じディレクトリーへ対象JARを置き、`-PcompatDistantHorizons`を追加します。これらの他MODはWaCameraのJARへ同梱しません。

過去に実施したForgeのシェーダー録画試験は、隔離した`run`でシェーダーパックを有効にして、上記のゲーム内試験へ`-PsmokeShaders`も指定する手順です。このモードは960×600の操作画面を使い、起動・地点コマンドに続けて昼夜の720p録画と実際の移動・建築を検査します。録画結果の影・発光・黒余白の確認には、保存された参照PNGとMP4の画素を使用します。1.0.1ではこの手順やNeoForgeのゲーム試験を実行していません。

## 残る確認範囲

- 一般ユーザーの各種ハードウェアでの1080p60性能、1時間の上限付近の録画。
- 1.0.1で移植したNeoForgeのIris 1.8.12＋Sodium 0.6.13における起動、実録画、画質、通常画面の維持、停止・再録画、性能。静的API照合はこれらの代わりにはならない。
- 上記以外の描画最適化MOD、NeoForge版の描画MOD互換、多数の他MODを含むユーザー環境、マルチプレイサーバーとの組み合わせ。
- 上記以外のシェーダーパック、録画中のパック切替・再読込、DHの大規模な遠景を含む実マップ。シェーダー付き二視点描画の長時間のGPUメモリ使用量と性能。
- Windows以外の環境、Windowsの個別オーディオデバイス構成。
- GPUコンテキスト喪失、電源断、ディスク障害など実機の故障注入。

alpha.2～alpha.3の実機ログには `glPushAttrib` / `glMatrixMode` 等の旧OpenGL APIに関するエラーが出ています。両版で録画と出力画像は正常でしたが、発生源は未特定です。これらの関数はWaCameraの撮影処理では呼んでいません。
