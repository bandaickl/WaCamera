# WaCamera 1.0.1 の使い方

この文書は1.0.1のソース／ローカルビルド向けです。GitHubで公開済みのReleaseは1.0で、NeoForgeのシェーダー録画移植は含まれていません。1.0.1のReleaseはまだ公開していません。

Minecraft 1.20.1版はForge 47.4.10以上・48未満とJava 17、Minecraft 1.21.1版はNeoForge 21.1.251以上・21.2未満とJava 21が必要です。録画の主な対応環境はWindows 11 x64です。

ローダーに合うJARをクライアント側へ入れ、ワールド内でKを押します。サーバーへの導入は不要です。

更新時は旧WaCameraのJARを`mods`から外し、新しいJAR一つへ入れ替えます。alpha.2から一人称プレイと別視点録画に対応しています。

alpha.5では、撮影設定を保存する10件の「パターン」と、1〜120倍の「録画倍率」を追加しました。既存のショット設定も引き続き読み込めます。

## ForgeでEmbeddium・Oculusを使う場合

alpha.4でEmbeddium併用時の起動クラッシュを修正し、シェーダーパックを有効にしたまま別視点を録画する処理を追加しています。Oculusの設定で使用するパックを選んでから、通常どおり撮影パネルの「別視点で録画」を開始します。シェーダーを使わない録画もできます。

確認に使った構成はForge 47.4.10＋Embeddium 0.3.31＋Oculus 1.8.0＋Distant Horizons 2.3.4-b＋Complementary Unbound r5.6です。960×600の操作画面を維持しながら、昼夜それぞれ8秒の1280×720・30fps動画を黒余白なく保存できました。[検証記録](testing-ja.md) の画像と確認範囲を参照してください。

撮影側にもシェーダー用の描画処理と画像を持つため、通常のシェーダープレイに加えてGPU負荷とメモリ使用量が増えます。初回の録画準備ではシェーダーの追加コンパイルが発生する場合があります。まず720p30で確認してください。互換APIやシェーダーの構築に失敗した場合は理由を表示します。

Forgeの機能は1.0から変更していません。ユーザーのMODパック全体や、上記以外のパック・バージョンの組み合わせは未検証です。

## NeoForgeでIris・Sodiumを使う場合

1.0.1で、Minecraft 1.21.1用の**Iris 1.8.12＋Sodium 0.6.13**を対象に独立したシェーダー録画処理を移植しました。Irisでパックを選び、撮影パネルから通常どおり録画する設計です。Iris・Sodiumはシェーダー利用時の追加構成で、シェーダーなしの録画には不要です。

確認したのは実JARのAPIとソースの整合です。利用者の希望により、今回Minecraft起動・自動テスト・実録画は行っておらず、NeoForgeでの映像・操作・性能は未検証です。ビルド確認の範囲と結果は[検証記録](testing-ja.md)を参照してください。

**NeoForgeのシェーダー有効＋Distant Horizons併用は未対応**です。該当する構成では理由を表示して録画を開始しません。使用する場合はDistant Horizonsを外すか、シェーダーを無効にしてください。録画中に未対応の状態や描画エラーを検知した場合は撮影を停止します。他のIris・Sodiumの版やシェーダーパック、MODパック全体の互換性も未検証です。

## コマンドで地点を設定する

alpha.3で追加しました。GUIと同じ撮影設定を編集します。

| コマンド | 動作 |
| --- | --- |
| `/wac cam` | 今の視点のXYZ・yaw・pitchを次の番号へ追加。最初は1、以後2、3… |
| `/wac cam 2` | 地点2を今の視点で登録・上書き。登録数は上書きでは増えない |
| `/wac cam 2 100.5 72.62 -20 90 15` | 地点2へXYZ・yaw・pitchを数値で指定 |
| `/wac goto 2` | 地点2の位置へ本人を移動し、保存したyaw・pitchへ向ける |
| `/wac help` | 使用方法を表示 |

番号は1～64で、登録済みの次の番号まで指定できます。例えば登録が1・2だけなら、番号なしは3、`/wac cam 2` は2を上書き、`/wac cam 3` は3を追加します。飛び番号は作らず、GUIの地点順と同じ番号を使います。初回にGUIを開閉しただけでは、未登録の初期地点を数えません。

XYZはカメラのレンズ位置です。数値入力は絶対座標のみで、`~`や`^`は使いません。yawは左右の向き、pitchは上下の向き（−90～90度、正が下向き）。登録した向きを撮影で使う場合は「視線：地点に登録した向き」を選びます。「自分を向く」などの自動注視を選んだ場合は、そちらを優先します。

`goto` はサーバーの通常のテレポートを要求します。シングルではチート許可、マルチではOP相当の権限が必要です。レンズのYから本人の目の高さを差し引いて足元座標を求めます。移動前後の姿勢で目の高さが変わらないよう、乗り物から降り、通常の立ち姿勢で実行してください。一人称で目線の位置と向きを確認できます。別ディメンションへは移動しません。録画・プレビュー・保存の処理中は地点編集と移動を受け付けません。

コマンド登録は編集中のショットへ反映します。次回起動後も使う場合は **K → パターン → この枠に保存**、または従来の **K → ショット → 設定を保存** を使ってください。

## GUIで編集・撮影する

「撮影地点」では、現在の視点を取得するか、XYZとyaw/pitchを入力します。XYZはレンズ位置で、プレイヤーの足元の高さとは異なります。一地点なら固定、複数なら移動撮影になります。地点を追加したい場所へ移動する際は、パネルを閉じて移動してから再度開きます。

「ショット」で秒数とカウントダウンを指定します。「なめらか」は三地点以上で曲線、二地点では直線です。「視線」を「自分を向く」にすると、カメラは経路に沿って移動しながら本人へ向きます。

別のワールドやディメンションで撮る場合は「ショット」の「新規」を押します。編集中の設定は別名で保存し、現在地から新しいショットを作ります。保存済みショットのディメンションを自動変更することはありません。

「録画設定」で品質と音声を選びます。初回の「録画エンジンを準備」はWindows x64用FFmpegを取得するため、インターネット接続が必要です。導入済みならFFmpeg欄に実行ファイルを入力できます。同じフォルダーにffprobeも必要です。

品質は720p24／720p30／1080p24／1080p30／1080p60から選べます。初期値は720p30です。「録画倍率（倍）」は1〜120で、小数も入力できます。倍率の使い方は下記を参照してください。

プレビュー後、「別視点で録画」を押します。プレイ画面は通常の一人称のまま、手・照準・HUDも表示されます。WASD・マウスやブロック操作は本人を操作し、登録したカメラが別視点の映像を録画します。録画にはプレイ用HUDやREC表示を入れません。プレビューだけは一時的に撮影カメラの視点へ切り替わります。

F8、設定時間の終了、ゲームの実際の一時停止、ワールド退出などで撮影を終えます。通常のシングルプレイではEscによる一時停止も該当します。マルチプレイ・LAN公開中のEscメニューや、インベントリー・チャットなどゲームを停止しない画面では録画を継続します。保存完了後に通知します。設定の保存ボタンで、同じ構図を再利用できます。

alpha.7から、別のウィンドウへ切り替えても録画は継続します。録画準備・カウントダウン・録画中は、フォーカスが外れたときの自動一時停止だけを抑えます。Minecraftの自動一時停止設定を変更する必要はなく、保存されている設定値も変更しません。録画後は通常の動作へ戻ります。プレビューはウィンドウを離れると終了します。

非アクティブ時のゲーム側FPS上限が撮影に必要な頻度より低い場合、録画中だけ上限を引き上げます。描画負荷はバックグラウンドでも発生します。GPUドライバーや他MODが描画を抑制する環境では、バックグラウンドでの実際のfpsが低下する場合があります。

## 録画中のカメラ位置・方向を確認する

alpha.6から、カウントダウンと別視点録画中は操作画面にカメラの目印が自動表示されます。

- 水色の小さなカメラ形状が撮影位置です。
- 黄色の矢印がカメラの向いている方向です。
- 水色の大きな枠が、画角と動画の縦横比を示すガイドです。カメラ前方2ブロックの位置で撮影範囲の広がりを表し、描画距離の上限を示すものではありません。

目印は移動経路と視線に追従し、壁越しでも見えます。倍速録画でも、目印は撮影間隔に合わせて止まらず、現在の経路位置を表示します。F1でHUDを隠すと目印も消えます。録画終了時やプレビュー中には表示しません。

目印は自分の操作画面にだけ描くガイドです。ワールドにブロックやEntityを置かず、当たり判定もありません。完成動画には入りません。

## パターンを保存・呼び出す

「パターン」タブには、A（1）〜J（10）の10枠があります。「ショット」で付けた任意の名前を、それぞれの枠へ保存できます。

1. 地点や視線、撮影秒数、録画倍率を編集し、「パターン」を開きます。
2. 保存したい枠を選び、「この枠に保存」を押します。既に保存済みなら、上書きの確認が出ます。
3. 再利用するときは枠を選び、「この枠を呼び出す」を押します。編集中の設定と異なる内容なら、置き換える前に確認が出ます。未保存の編集を残す場合はキャンセルして先に保存してください。

保存されるのは名前、ディメンション、全地点のXYZ・yaw/pitch・順序、視線モードと注視座標、FOV、経路の補間方法、撮影秒数、カウントダウン、録画倍率です。呼び出すと編集画面へ復元されます。本人を移動させる操作ではなく、録画も自動開始しません。別ディメンションの設定は、そのディメンションへ移動するか新しい設定を作ってから使います。

保存先はゲームフォルダー内の `wacamera/patterns/pattern-01.json` 〜 `pattern-10.json` です。枠は番号で管理するため、別の枠に同じ名前を付けても互いを上書きしません。名前は自由ですが、空欄にはできず80文字までです。画質、音声の選択、FFmpegの場所など、このPCの録画環境はパターンに含みません。

従来の名前付き保存は「ショット」タブから使え、`wacamera/shots/` に件数制限なく保存します。旧形式のJSONは読み込み時に録画倍率1倍として新形式へ移行し、次に保存すると `schemaVersion: 2` になります。読み込むだけで元のファイルを書き換えることはありません。

## 倍速動画を録画する

「録画倍率」は完成動画の速さです。例えば撮影時間60秒・10倍なら、実際には60秒間撮影し、約6秒の動画を保存します。ゲームの進む速さや本人の操作は変わりません。カメラ経路も設定した実時間で移動し、プレビューは通常速度で再生します。

出力fpsを倍率で割った頻度で、撮影用の追加描画と画像取得を行います。後から全フレームを倍速に変換する方式ではありません。

| 品質と倍率の例 | 実時間での画像取得 | 完成動画 |
| --- | --- | --- |
| 24fps・1倍、60秒撮影 | 24枚/秒 | 24fps、60秒 |
| 24fps・10倍、60秒撮影 | 2.4枚/秒 | 24fps、約6秒 |
| 30fps・2.5倍、60秒撮影 | 12枚/秒 | 30fps、約24秒 |

1倍を超える録画は無音です。音声の選択自体は保持され、1倍へ戻すと元の音声設定を使います。倍速録画のために音声補助プログラムを起動することはありません。

動画は1フレーム単位で長さが決まるため、「撮影秒数÷倍率」から1フレーム未満の端数差が生じます。10倍ならファイル容量が必ず10分の1になるという保証はありません。画面の動き、画質、圧縮率にも左右されます。画像取得の間に起きた短い動きは記録されないため、建築などの経過を短くまとめる用途に向きます。

## 音声

1倍で音声を有効にした録画では、Windowsのプロセス単位キャプチャーを使用し、Minecraft内で再生される音を取得します。同じプロセスのボイスチャットMODの音も入り得ます。別アプリの通話音やマイクを録る機能ではありません。1倍を超える録画は音声設定にかかわらず無音です。

対応APIが使えない場合はエラーになります。PC全体の音へ自動的に切り替えることはありません。音声が不要なら録画設定で無音を選びます。開発時の自動Minecraftテストはマスター音量を0にし、ファイルの検査も再生なしで実行します。

## 制限

- プレイ用と撮影用でワールドを二回描画するため、録画していない時よりGPU負荷が増えます。初めは720p30を推奨します。
- 読み込み済みの周辺地形を撮ります。カメラだけを遠くへ動かしても、サーバーから未受信の地形を増やせません。
- 処理落ち時は画像を複製して動画の長さを維持しますが、失われた動きは復元できません。
- 録画はウィンドウとは別の720p／1080p・16:9ターゲットへ描画します。小さなプレイ画面でも録画解像度は選択した設定を維持します。
- ウィンドウサイズを変更しても、録画用ターゲットの大きさは変わりません。
- 障害物の自動回避はありません。経路はプレビューで確認してください。
- シェーダーの実録画を確認した範囲は上記のForge構成です。NeoForgeの1.0.1の移植は実JAR API・ソース照合までで、実録画は未検証です。その他のパック、MOD、バージョンまで動作確認済みとは扱いません。
- Fabulous設定のときも、録画側はFancy相当の描画になります。プレイ画面の画質設定は変更しません。透過面の並べ替えなど、一部の描画情報はプレイ視点と共有する制限があります。

## 保存に失敗した場合

`wacamera/recordings/.wacamera-recovery/` に、仕上げ前の映像・音声・時刻情報・ログを残します。保存成功の確認前に消さないでください。容量不足やエンコーダー設定を直してから回復を試せます。クラッシュの時点や破損内容によっては回復できないこともあります。

撮影パネルの「回復」で未完了の録画を選び、元の音声設定で回復します。音声データが壊れている場合は、明示的に「無音で回復」を選べます。処理中の録画は選べません。元データは残し、回復したMP4は別名で保存します。
